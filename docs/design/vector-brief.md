# Vector device brief

Vector supports deep four-operator FM sound design through a clean, direct workflow. It inherits Hex’s purpose and conventions from the [project overview](../../README.md), uses the [shared device host](device-host-brief.md), and follows the local Codex product design philosophy. Its musical depth is Operator-inspired; its visuals and general modulation belong to Hex.

## Working surface

Every oscillator uses a compact two-row layout: ratio and level above, fine Hz offset and waveform below. Every oscillator exposes ratio, fine Hz offset, one filled horizontal dB level slider, waveform choice, and its own keytrack slider. Fixed routing presets, feedback, filter cutoff/resonance and envelope amount, a voice-count dropdown and glide remain available while editing envelopes. Custom routing is outside the first iteration. Phase/retrigger live in a narrow optional oscillator panel; voice count is directly exposed in place of the mono/poly button, with concept choices 1, 2, 4, 8, 16 and 32 (default 8; 1 voice is mono). It is not duplicated in device settings. General modulation uses host modulators.

## Envelope editing

Selection is explicit: clicking an oscillator section background selects its envelope; the left colored rectangle only toggles oscillator power. Noninteractive a/b/c/d letters identify the rows without separate selector buttons. Cutoff, resonance and env peak belong to one filter section, whose background selects its envelope without a separate Env button. Parameter controls consume their own interaction, so level/tuning and cutoff/resonance edits never switch the envelope editor. The selected section has a restrained blue fill and outline, and its background selection target participates in keyboard navigation. One oscillator envelope is editable, with the other three ghosted on the same locked nonlinear time scale. Filter selection replaces this with its one independent envelope. ADSR values and curve shaping remain directly accessible. Initial/peak levels and the three segment-curve amounts are always visible in a compact numeric row below ADSR. The plot is shorter vertically to make room for these working controls; its shared time scale stays locked. Editing these fields preserves the explicitly selected envelope. Initial/peak, decay/sustain and release points have clear handles and contextual exact readouts. Selected point names occupy a compact header area separate from their exact-value field; source identity remains visible. Use familiar d/s and a/d/r curve abbreviations in this header, with f identifying the filter. Compact combined times use ms/s; full parameter names remain available through contextual help. Segment-curvature handles stay on the graph; keyboard focus has a distinct light outline. Active curves paint above ghosts.

All four oscillator envelopes share these ranges: attack 0 ms–20 s; decay 1 ms–60 s; sustain −∞–0 dB; release 1 ms–60 s. These are user-verified displayed Operator ranges, not claims of identical DSP behavior. The filter envelope uses normalized 0–100% levels. Its bipolar depth spans −96 to +96 semitones, defaults to 0 st and supports fine adjustment. Cutoff displays the base frequency; the always-visible `env peak` control displays the calculated destination frequency at the edited envelope peak level. The parameter, drag scale and precise entry remain semitone-based; the normal readout uses Hz/kHz. The calculation is base cutoff × 2^(depth × peak level / 12), with peak level represented from 0 to 1. Changing base cutoff or graph peak updates that readout. At 500 Hz and +24 st, a 50% graph peak therefore displays 1 kHz. Positive amounts raise cutoff; negative amounts lower it. The cutoff offset equals envelope level × amount in semitones, bounded by the supported filter cutoff range. A 500 Hz cutoff with +24 st reaches 2 kHz at a 100% peak and 1 kHz at 50% sustain; release to 0% returns to the base cutoff. Editing amount preserves envelope selection. During precise entry, the field temporarily shows the semitone amount, with its calculated frequency and ±96 st range in a contextual hint; normal display returns to frequency.

Attack and decay loop; release remains outside the loop. Free looping follows authored timing. Tempo sync fits the loop to a beat division. Note-pitch sync fits it to the played-note period, with a ratio such as 0.5×, 1× or 2×. Both synced modes preserve relative stage timing and curves. Their attack/decay fields show shape proportions; a cycle/rate caption explains effective timing. Free-loop readouts and first-cycle shading derive from the selected attack plus decay. A fainter held region and repeat bracket continue to an explicit note-off marker, followed by the separately labelled release. The graph shows a vertical return to initial and a second A/D cycle, with the held region indicating continued repetition. Preview fixtures use 120 bpm, a 440 Hz played note and a shared 2 s note-off; these are examples, not native timing constants. Timing controls appear only with looping enabled. Note-off exits immediately into the normal release time from the current level. All three modes reset immediately to the envelope’s initial level after decay, then repeat the same A/D shape. This return takes no extra time and does not restart oscillator phase. Note-off takes priority over a simultaneous reset, starting release from the pre-reset current level. There is no alternate restart option in the first iteration. When sustain differs from initial, the boundary is discontinuous; the graph shows that jump explicitly. Matching those levels makes the boundary continuous.

## Waveform editing

The curve/harmonics editor expands immediately to the right of the oscillators. Size optional panels to their contents: settings and oscillator options use less width than this editor. Changes audition live; there is no Apply/Cancel. Closing the panel keeps edits; Undo restores unwanted changes. Native freehand editing, audio preview, and gesture-level Undo remain implementation requirements. The Frame document provides illustrative edited states, not synthesis.

## Visual and keyboard direction

Keep a 200 px device height and expand horizontally. The initial view has host panels closed, with separate open-panel previews. Ratio/Hz controls use horizontal fill tracks; glide has a visible on/off state and retains its configured time. The routing diagram is itself the preset picker and opens diagram-based choices; remove the redundant routing label and text picker. Diagrams use small colored square nodes matching the oscillator colors, without operator letters, and short directional paths to identify topology, output and the fixed feedback target. Use the same compact drawing language in the preset picker. The right-hand block uses aligned label/value rows for feedback and the filter, with voicing controls aligned along the bottom. Use neutral graphite surfaces, blue selection, restrained oscillator colors and readable lowercase Ioskeley Mono text. Keep the 200 px height and favor small elements and compact layouts. Reclaim unnecessary width, padding and repeated text while retaining readable working values. Size value fields for their expected formatted range so editing does not shift the layout. Exact point values use at least 9 px type. Four-high macro slots place their values beside the knob rather than over its pointer. The voice-count dropdown keeps the selected value marked, uses arrows to navigate, Enter to choose and Escape to close. Tab exposes controls in a logical order; selecting editor contexts and opening panels do not change sound parameters. Keyboard value editing preserves normal text entry. Section selection, routing choices and graph handles have explicit keyboard-focus previews; graph-handle focus uses an outer ring distinct from its selected point. Precise graph keyboard gestures remain to be defined.
