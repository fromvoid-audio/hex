## closed Utility construction and actual origins

Private audio preparation accepts audio tracks with the existing Utility family;
other DSP, instruments, MIDI, Return processors and signal-graph compensation
remain refused. Utility uses the same concrete fixed-inline constructor as its
registered implementation. No caller-created processor, prepared Arc or runtime
is adopted. The constructor preserves both host trims and the existing segmented
source/mix ordering.

Each prepared entry retains declarations for its actual configuration allocation,
separate nested immutable state payload, meter and optional concrete prepared
processor. Inner payload identity differs from equal state values. Each actual
owning handle is listed independently; scalar strong/weak observations establish
neither provenance nor lifetime closure. Temporary entry Vec conversion overlap
and retained declaration Vec capacity remain charged. The borrowed PR233 ledger
still refuses `require_complete`.

A private origin is constructor runtime identity (including its incarnation) plus
original member. Supported operations never refill an owning location with a
fresh owner inside that runtime. This is why a further per-location incarnation
is unnecessary for this closed class; widening that invariant needs new proof.

The pre-reserved transfer journal is planned from the actual Session handoff's
TrackChain-to-TailChain and TailChain-to-TailChain selection. Origin association
commits with those real owner moves. History copied into an independently
constructed chain receives no transfer credit. Unsupported analytic-context,
mutable-instrument, Return-tail or compensation movement refuses. The current
class's actual audio-only operations leave those locations absent.

Normal actual Runtime Box destruction produces a move-only remaining-origin
book. Atomic ingestion validates every affected archive and original runtime
before closing any origin. The original preparation custody, source bank/token
and charges cannot be released while any descendant origin remains open. A
physical runtime fact alone cannot release its prepared graph or original PCM.
Duplicate reports refuse; panic retains the first payload and does not retry.

The real A-to-B-to-C control warms three Utility chains. Removing x/y moves their
actual primary/scratch Boxes into B tails; z remains A. After real rendering the
fast y filter is quiescent while x is active, so only x crosses to C. Independent
normal A/B/C destruction closes z/y/x; original bank Vec pointers and capacities
survive. Primary/scratch roles may swap at a normal DSP block commit, so identity
checks compare the actual physical pair independently of role.
