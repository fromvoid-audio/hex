# Pulse task #2469: Unify native device widgets and layout around Operator/Vector

Operation: 686da72b2211eeef0c9bd308c89b2fd6
Assignee: PORTALSURFER (Pulse #1, GitHub ID 41680373)

Goal: all native devices use a flexible, unified GUI system in hex-widgets. Operator (user-facing rename Vector; source still Operator) supplies the accepted layout/focus reference, while the application theme supplies colors. Preserve Operator layout and interactions. Its fixed grays are too light; only a selected header should highlight, with no selected outer border. Other device shells, rounded sections, widgets and header heights must follow the same system.

Explicit architectural rule from the user: devices may compose different interfaces and use different useful widths. When a new device requires a visual/layout capability, implement that capability as a reusable widget or layout feature in the shared library first. Do not add custom device-local styling. The library must accommodate functionality rather than force every device into an identical arrangement. Restrict panels to composition, validated parameter/display mapping and canonical bindings. Product theme preferences remain in hex-ui/hex-preferences; widgets accept semantic colors and remain independent of DSP/project state.

Audit conducted 13 October 2026 on clean checkout a882f9d2c1d83b73b3e850d1b49dbfff24607e94; source-only evidence, no native render, source edits or build. Full live Hex ticket inventory returned 200 tickets; reviewed matching toolkit/frame/theme/gallery/Operator work. Reuse #44 and #2242 foundations and extend #2355/PR163 gallery; preserve completed acceptance/history. Separate from active #2345 control-focus indicators, #2373 Tab behavior, #2352 readouts, #2463 typing, and Operator DSP work.

Confirmed gaps:
- hex-widgets/frame.rs exports standard 18px and compact 14px headers, with different padding/gaps. device_panel.rs dispatches Sine/generic instruments to standard but Operator and dedicated effects to compact; return_view.rs repeats the distinction.
- Shared frame defaults use Surface body and Raised header with a divider. Operator frame_style overrides background/surface/raised/border to #474747, its rail to #363636 and display to #191919. Application default background is #2a2828. Operator's merged idle header/surround is the layout reference, but fixed neutral colors bypass theme.
- Rounded Operator rows/sections/display and all other device columns/gutters are constructed locally; the library has no reusable device-section/body-layout API. Dedicated device widths and DSP plots are legitimate; per-device chrome rules are not.
- device_panel.rs special-cases Operator InlineValue styles by type ID in both creation and refresh. display_style also hardcodes gray/rail colors. Semantic layout/control context should choose styling without device-identity branches.
- Existing native layout_review gallery shares frame/tab components but hardcodes its palette, maintains two header variants and hand-builds composite headers at 20px plus sections. Its approval does not guarantee production conformity.
- Source guards cover dependency boundaries/lowercase/font, not shared section/style usage. Existing rendered tests cover individual panel geometry and gallery interaction, not catalog-wide style/paint consistency.
- Header-plus-border selection is user-reported; not reproduced from an actual current candidate here. The shared frame has no explicit selection-state contract. Gallery owns separate selection state. Production's full-border instrument-replacement drop overlay is a separate affordance, not established as the selection defect; preserve it unless actual evidence justifies changing it.

Coverage matrix:
Operator/Vector: shared compact shell plus custom gray frame/rows/display/readouts.
Sine and generic instruments: shared standard shell, wrapped generic controls; taller header.
Utility: compact shell; local input/output columns/divider.
Gate and Auto Pan: compact shell; local columns without Operator section hierarchy.
Compressor and Saturator: compact shell; local graph/control grouping.
EQ8: compact shell; local band/main/graph/control grouping.
Generic effects and unsupported-state paths: standard or type-specific shell.
Return effects: duplicate dispatch and style paths that must migrate with Track effects.
Review gallery: partial production reuse plus independent palette/chrome.

Five implementation obligations: shared extensible layout contract; palette and semantic styles; header-only selection; all-device migration; production-backed review gallery, rendered regressions and enforcement. Suggested order and dependencies are in child drafts. No DSP/schema/type-ID rename or parameter-law changes. No claim that these tickets are created, implemented, tested or accepted until supported writes and checks succeed.
