## Recommended bounded production plan (await root acceptance)
A. Remove ONLY prepare's blanket HEX_DEV_APP_PATH rejection. Keep launch.configured_app as sole configuration resolver, same absolute persistent target, same non-symlink path checks, signature/receipt verification, activation/target exclusions, owner CAS and recovery. No new override, compiler or search path.
B. Retain actual path strings as descriptive identity, but use verified filesystem identity for target membership. Do not casefold whole paths or resolve symlinks into trust. Accept basename hex.app case-insensitively as existing configured_app does. All configured and candidate bundle/executable path components must remain non-symlinks.
C. Add four private identity pins: bundle_device, bundle_inode, executable_device, executable_inode (positive/bounded integer validation, explicitly reject Python bool). Swift reads lstat-backed device/inode and requires directory bundle and regular executable. Candidate bundle AND executable pins must equal the configured bundle and configured Contents/MacOS/hex pins. Exact identifier remains org.portalsurfer.hex.dev. Python validates returned pins against its verified target; retain the observed native spelling in Identity. Native request validates expected pins against target and observed application immediately before termination, twice as current code does; PID/start/identifier/full Identity equality stays mandatory. This binds the selection to one actual filesystem target even across harmless casing spellings, and refuses same-spelled replacement inodes without trusting a lowercase string. No protocol version migration; helper/source compiled as one source unit.
D. Extend existing installed seal with bundle device/inode alongside existing executable device/inode/SHA so a directory replacement also refuses across cold compilation. No new owner/service/cache or process-discovery fallback. Keep strict original executable hash/signature verification. Snapshot of absent target remains [] and must never adopt an unverified running app; quit/force on absent target refuses. Define missing-target handling explicitly before any stat lookup to preserve already-qualified ABSENT behavior.

Why additive pins: merely calling samefile on current target and current candidate does not carry the original target inode through snapshot→compile→request; merely projecting requested path strings conceals replacement. Four private fields keep before/after identity explicit, without adding a generic security framework. This is a proposal, not an implemented or qualified change.
